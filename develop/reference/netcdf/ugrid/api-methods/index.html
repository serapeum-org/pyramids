    UgridDataset — Complete Method Reference#

    UgridDataset exposes 143 public methods and 19 properties. Many are inherited from the _UgridFacades mixin and do not appear directly on the class definition, making them hard to discover via code search or LLM introspection. This page lists every public method and property grouped by category.

    Source files: methods marked (F) live on _UgridFacades (_facades.py); those marked (D) live directly on UgridDataset (dataset.py).

    Properties#

    Property Source Description
    mesh (D) The Mesh2d topology object
    mesh_name (D) Name of the mesh topology variable
    data_variable_names (D) Names of all data variables
    crs (D) CRS as pyproj.CRS, or None
    epsg (D) EPSG code of the CRS, or None
    crs_wkt (D) CRS as WKT string, or None
    bounds (D) Bounding box (xmin, ymin, xmax, ymax)
    global_attributes (D) File-level NetCDF attributes dict
    n_node (D) Number of mesh nodes
    n_face (D) Number of mesh faces
    n_edge (D) Number of mesh edges
    data_vars (D) Copy of the {name: MeshVariable} mapping
    metadata (D) Full metadata summary (UgridMetadata)
    time_values (D) Parsed time coordinate values, or None
    volume_topology (D) Ragged vertical layering, or None
    n_volume (D) Total number of 3-D volumes, or None
    n_layers (D) Number of vertical layers, or None
    n_layer_interfaces (D) Number of layer interfaces, or None
    layer_values (D) Layer coordinate values, or None

    Temporal Operations#

    Behaviour change: time_values now carries decoded dates

    For a file whose time variable declares CF units ("<interval> since <origin>"), time_values and to_dataframe()["time"] return decoded stamps — numpy.datetime64 for the Gregorian calendar family, cftime objects for a model calendar such as 360_day. They previously returned positional integers for those files.

    # before
ds.time_values            # [0, 1]
# after
ds.time_values            # [datetime64('2001-05-05T00:00:05'), ...]

    Code that treated the values as integers (ds.time_values[0] + 1, or comparing against 0) needs updating. A file carrying no CF time units is unaffected and still reports positional indices, so the fallback behaviour is unchanged.

    This lands as a behaviour change within the 0.x line rather than as a major release: returning positional indices for a file that states its stamps was the defect #1381 describes, so the decoded values are the fix. The note is here because the element type nevertheless changes for files that already carried CF units.
