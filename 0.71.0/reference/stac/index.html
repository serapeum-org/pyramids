    STAC Subpackage#

    The pyramids.stac subpackage connects pyramids to the SpatioTemporal Asset Catalog ecosystem — searching STAC APIs, reading assets as pyramids Dataset / NetCDF objects, building cubes, signing cloud credentials, and writing STAC Items back out. Everything is GDAL-native (no rasterio, no labeled-array stack) and duck-typed over the STAC Item/Asset contract, so pystac is never imported by pyramids itself — raw STAC JSON dicts work as well as pystac.Item objects.

    Two STAC entry points live on the raster classes (documented there):

    • DatasetCollection.from_stac(items, asset, *, patch_url, bbox, max_items, signer, groupby, alignment, tolerance, fusion, read, provenance) — build a time-stacked cube from STAC items (single asset → time stack, or a list of assets → band axis). groupby takes "solar_day", "id", "time", any item property key, or a callable, and each group is mosaicked with GroupFusion(method=...) (first/last/min/max/sum/count/mean) or a custom GroupFusion(fuse_func=...). Alignment(grid=...) matches a target grid, AssetRead(rescale=True) returns physical units, AssetRead(cfg=...) supplies missing metadata and band aliases, and ReadTolerance(errors_as_nodata=True) fills a nodata plane for an unreadable asset instead of losing the cube. See DatasetCollection.
    • DatasetCollection.from_point(lat, lon, *, collection, bands, start_date, end_date, edge_size, resolution) — a cubo-style point + edge-size convenience cube. See DatasetCollection.
    • Dataset.to_stac_item(item_id, *, asset_href, …, bands, footprint, extensions) — describe a raster as a STAC Item dict, with BandMetadata choosing how much per-band metadata is published, Footprint how the geometry and bbox are derived, and StacExtensions which extension blocks (proj, raster) are stamped. See I/O.

    Install#

    open_client / search need the [stac] extra (which also bundles the optional asset downloader stac-asset); read_extension_metadata, load_asset, build_vrt_from_stac, to_stac_item, and the signers need only core pyramids:

    pip install 'pyramids-core[stac]'           # client/search + download_item
pip install 'pyramids-core[stac,parquet]'   # + GeoParquet round-trip

    See the STAC tutorial for an end-to-end walkthrough, the offline STAC notebook, and the live-endpoint notebooks for Earth Search (anonymous) and the Planetary Computer (signed).

    Option objects#

    The frozen, all-defaulted groups the two entry points take. Each is re-exported from pyramids.stac, so from pyramids.stac import Alignment, Footprint is the import to use.

    pyramids.dataset.stac_options #

    Grouped option objects for the two public STAC entry points.

    :meth:pyramids.dataset.Dataset.to_stac_item and :meth:pyramids.dataset.DatasetCollection.from_stac each grew past twenty keyword arguments, most of which are only meaningful next to two or three of their neighbours. The options that travel together are gathered here, one frozen dataclass per group, so each entry point takes one object per concern instead of a flat list of flags.

    Every dataclass defaults every field, so each is optional at the call site and None means "all defaults for that group": to_stac_item(ds, "id", asset_href=...) and from_stac(items, "red") are unchanged.

    The module is a leaf: it imports nothing from pyramids at run time (only numpy and the standard library), which is what lets :mod:pyramids.dataset._stac import it at module load without reviving the dataset ↔ stac import cycle. It lives under :mod:pyramids.dataset for the same reason :mod:pyramids.dataset._stac does — importing pyramids.stac.anything initialises the :mod:pyramids.stac package, whose __init__ imports :mod:pyramids.dataset — and every name here is re-exported from :mod:pyramids.stac, which is where callers should import it from.

    Group behaviour that has to touch GDAL (measuring a band, resolving a footprint) stays in :mod:pyramids.dataset._stac beside the helpers it calls; what lives here is each group's data and the validation that data can answer on its own.

    BandMetadata dataclass #

    How much per-band metadata an Item's asset pays to publish.

    with_stats, with_histogram, histogram_bins and stats_approx_ok are born together, are forwarded as a block and are read at a single point per band; with_eo joins them because it is the third opt-in band block. They share one property no other :meth:~pyramids.dataset.Dataset.to_stac_item option has — each asks GDAL to look at the raster's bands, and each degrades by omitting its field with a warning rather than failing the Item — so they are one concept: how much band measuring this Item pays for.

    Attributes:

    Name Type Description
    with_stats bool

    Add a per-band statistics object (minimum, maximum, mean, stddev, in physical units) to raster:bands. A band with no valid pixels is skipped with a warning.
    with_histogram bool

    Add a per-band histogram object (count, min, max, buckets) to raster:bands. A band with no value range (constant or all-nodata) is skipped with a warning.
    histogram_bins int

    Number of histogram buckets when with_histogram.
    with_eo bool

    Add eo:bands (band names) to the asset and the eo schema to stac_extensions.
    stats_approx_ok bool

    Let GDAL answer with_stats from overviews or a subsample (fast); pass False for exact figures.

    Examples:

    • The default group measures nothing, so an Item costs no band reads: 
      >>> from pyramids.stac import BandMetadata
>>> bands = BandMetadata()
>>> bands.with_stats, bands.with_histogram, bands.with_eo
(False, False, False)
>>> bands.histogram_bins
10
    • Opt into statistics and a 32-bucket histogram, and ask for exact figures: 
      >>> from pyramids.stac import BandMetadata
>>> bands = BandMetadata(
...     with_stats=True,
...     with_histogram=True,
...     histogram_bins=32,
...     stats_approx_ok=False,
... )
>>> bands.histogram_bins
32
>>> bands.stats_approx_ok
False
    • Hand the group to to_stac_item and read the blocks it published: 
      >>> import numpy as np
>>> from pyramids.dataset import Dataset, GeoReference
>>> from pyramids.stac import BandMetadata
>>> ds = Dataset.from_array(
...     np.array([[1.0, 2.0], [3.0, 4.0]], dtype="float32"),
...     geo_ref=GeoReference(top_left_corner=(0.0, 2.0), cell_size=1.0, epsg=4326),
... )
>>> item = ds.to_stac_item(
...     "scene-1",
...     asset_href="scene.tif",
...     datetime="2023-06-01T00:00:00Z",
...     bands=BandMetadata(with_stats=True, with_eo=True),
... )
>>> stats = item["assets"]["data"]["raster:bands"][0]["statistics"]
>>> stats["minimum"], stats["maximum"], stats["mean"]
(1.0, 4.0, 2.5)
>>> item["assets"]["data"]["eo:bands"]
[{'name': 'Band_1'}]
    See Also
    • StacExtensions: which extension blocks the Item declares at all.
    • pyramids.dataset.Dataset.to_stac_item: the entry point that consumes this group.

    Footprint dataclass #

    How an Item's geometry and bbox are derived from a dataset's extent.

    The six footprint* / geometry keywords of :meth:~pyramids.dataset.Dataset.to_stac_item are born together, are never read apart, and are consumed at a single point — the one step that turns a dataset into (geometry, bbox). The two readings of the mode, the no-EPSG fallback and the antimeridian split all read nothing but this clump plus the dataset's own extent. precision belongs here because the reprojected footprint's coordinates are the only thing it ever rounds.

    Attributes:

    Name Type Description
    mode str

    "bbox" (default) for the dataset's bounding rectangle, or "data" for the polygonised extent of its valid (non-nodata) pixels. Both paths need an EPSG code to reach EPSG:4326, so a dataset whose CRS has no EPSG authority code cannot be reprojected: "data" is then declined with a RuntimeWarning and the bbox path's world-extent fallback applies.
    band int

    Zero-based band to footprint in "data" mode.
    max_samples int | None

    Approximate pixel budget for the valid-pixel mask — accuracy traded for speed — or None for an exact read.
    simplify_tolerance float | None

    Douglas-Peucker tolerance in degrees, applied to the data footprint after reprojection, or None to keep every vertex.
    densify float | None

    Maximum segment length in native CRS units, applied to the data footprint before reprojection so long edges follow the projection's curvature; None/0 leaves the edges alone.
    precision int

    Decimal places for the reprojected footprint coordinates.

    Examples:

    • The default group is the bounding rectangle at six decimals: 
      >>> from pyramids.stac import Footprint
>>> footprint = Footprint()
>>> footprint.mode
'bbox'
>>> footprint.precision
6
>>> footprint.max_samples, footprint.simplify_tolerance, footprint.densify
(None, None, None)
    • Ask for the valid-pixel footprint, rounded to two decimals, and read the geometry it produced — only the one valid pixel is covered, not the full grid: 
      >>> import numpy as np
>>> from pyramids.dataset import Dataset, GeoReference
>>> from pyramids.stac import Footprint
>>> ds = Dataset.from_array(
...     np.array([[1.0, np.nan], [np.nan, np.nan]], dtype="float32"),
...     no_data_value=np.nan,
...     geo_ref=GeoReference(top_left_corner=(0.0, 2.0), cell_size=1.0, epsg=4326),
... )
>>> item = ds.to_stac_item(
...     "scene-1",
...     asset_href="scene.tif",
...     datetime="2023-06-01T00:00:00Z",
...     footprint=Footprint(mode="data", precision=2),
... )
>>> item["bbox"]
[0.0, 1.0, 1.0, 2.0]
>>> item["geometry"]["coordinates"]
[[[0.0, 2.0], [0.0, 1.0], [1.0, 1.0], [1.0, 2.0], [0.0, 2.0]]]
    • Any other mode is rejected on construction, before a dataset is touched: 
      >>> from pyramids.stac import Footprint
>>> Footprint(mode="outline")
Traceback (most recent call last):
    ...
ValueError: footprint must be 'bbox' or 'data', got 'outline'.

    ReadTolerance dataclass #

    What :meth:~pyramids.dataset.DatasetCollection.from_stac does with an Item whose asset is not usable.

    The two failures a build can forgive, and the pair the documentation contrasts: an asset the Item never declared, and one it declares but that will not open. Both answer "drop it or stop", both are independent of the other's answer, and both are read at the same points, so they belong together — while staying two fields, because the metadata gap and the IO failure are genuinely different events.

    Attributes:

    Name Type Description
    skip_missing bool

    When True, items lacking the asset key are dropped instead of raising. When False (default), a missing asset raises :class:~pyramids.base._errors.StacAssetError. This is about the item's metadata only — an asset that is declared but cannot be read is a different failure, covered by errors_as_nodata.
    errors_as_nodata bool

    Tolerate an asset that is present on the item but cannot be opened (404, expired signed URL, unreachable host, a file truncated badly enough that its header will not parse) by substituting a no-data-filled (NaN) plane for that timestep instead of failing the whole cube. Only IO/open errors (OSError, GDAL's RuntimeError) are converted; a missing asset key, a bad argument or any other programming error still raises — that is skip_missing's job, and the two are independent.

    Only the open is probed. A raster whose header parses but whose tiles are truncated opens cleanly and then fails later, on the lazy pixel read, by which point the cube is built and no plane can be substituted for it. So partial corruption is not covered, however the failure is spelled; a header that does not parse is.

    The plane needs a grid. The reference grid is :attr:Alignment.grid when one is given, otherwise the grid of the first timestep that does open — one grid for the whole build, not one per group. A grouped build fills an empty group (every source unreadable) from that same reference, so in a collection spanning several UTM zones or resolutions the plane necessarily lands on another group's grid and the cube then mixes grids. The substitution warns when it borrows a grid this way, but Alignment(grid=...) is the only way to pin it, so treat it as effectively required for a heterogeneous collection. When nothing opens and no grid was given there is nothing to fill, so a ValueError is raised. Each substitution emits a warning with the href redacted (credentials stripped).

    In single-asset mode this forces an eager open probe of every href (the hrefs themselves stay the collection's backing files, so reads remain lazy); a lazy build cannot discover an unreadable URL until it is too late to substitute anything.

    GroupFusion dataclass #

    How a group's overlapping pixels resolve into one timestep.

    method and fuse_func are two spellings of a single decision — the overlap-resolution rule for a mosaicked group — which is why they are mutually exclusive and why neither means anything without a groupby. One object makes the exclusivity visible at the call site.

    Attributes:

    Name Type Description
    method str

    The overlap-resolution rule handed to :func:~pyramids.dataset.merge.merge_rasters when a group's items are mosaicked: "first" (default, first-valid pixel wins), "last", "min", "max", "sum", "count" or "mean". Passing anything but "first" without a groupby raises.
    fuse_func Callable[[ndarray, ndarray], None] | None

    An odc-style in-place fuser (dst, src) -> None that replaces the built-in mosaic for every group: the group's sources are read onto the first source's grid, no-data is normalised to NaN, and the callback is applied pairwise in item order, mutating the accumulator. Its return value is ignored. Mutually exclusive with a non-default method, and rejected when groupby is None. None (default) keeps the built-in merge.

    Examples:

    • The default group is the first-valid-pixel mosaic, with no custom fuser: 
      >>> from pyramids.stac import GroupFusion
>>> fusion = GroupFusion()
>>> fusion.method
'first'
>>> fusion.fuse_func is None
True

      >>> import numpy as np
>>> from pyramids.stac import GroupFusion
>>> def keep_max(dst, src):
...     np.fmax(dst, src, out=dst)
>>> fusion = GroupFusion(fuse_func=keep_max)
>>> fusion.method
'first'

class GroupFusion:
    """How a group's overlapping pixels resolve into one timestep.

    `method` and `fuse_func` are two spellings of a single decision — the
    overlap-resolution rule for a mosaicked group — which is why they are
    mutually exclusive and why neither means anything without a `groupby`. One
    object makes the exclusivity visible at the call site.

    Attributes:
        method: The overlap-resolution rule handed to
            :func:`~pyramids.dataset.merge.merge_rasters` when a group's items
            are mosaicked: `"first"` (default, first-valid pixel wins),
            `"last"`, `"min"`, `"max"`, `"sum"`, `"count"` or `"mean"`. Passing
            anything but `"first"` without a `groupby` raises.
        fuse_func: An **odc-style in-place fuser** `(dst, src) -> None` that
            replaces the built-in mosaic for every group: the group's sources
            are read onto the first source's grid, no-data is normalised to
            `NaN`, and the callback is applied pairwise in item order,
            mutating the accumulator. Its return value is ignored. Mutually
            exclusive with a non-default `method`, and rejected when `groupby`
            is `None`. `None` (default) keeps the built-in merge.

    Examples:
        - The default group is the first-valid-pixel mosaic, with no custom fuser:
            ```python
            >>> from pyramids.stac import GroupFusion
            >>> fusion = GroupFusion()
            >>> fusion.method
            'first'
            >>> fusion.fuse_func is None
            True

            ```
        - A custom in-place fuser is kept as given and mutates its accumulator:
            ```python
            >>> import numpy as np
            >>> from pyramids.stac import GroupFusion
            >>> def keep_max(dst, src):
            ...     np.fmax(dst, src, out=dst)
            >>> fusion = GroupFusion(fuse_func=keep_max)
            >>> fusion.method
            'first'
            >>> accumulator = np.array([1.0, 5.0])
            >>> fusion.fuse_func(accumulator, np.array([3.0, 2.0]))
            >>> accumulator.tolist()
            [3.0, 5.0]

            ```

            ```python
            >>> from pyramids.stac import GroupFusion
            >>> GroupFusion(fuse_func="max")
            Traceback (most recent call last):
                ...

            ```

    How each asset's values and metadata are normalised as they are read.

    rescale and cfg are the only two reasons :meth:~pyramids.dataset.DatasetCollection.from_stac has to rewrite a source rather than read it as it stands, they decide together whether a timestep is materialised instead of staying a lazy URL, and they are threaded to exactly the same places. They are one concept: what the reader fixes up on the way in.

    Attributes:

    Name Type Description
    rescale bool

    Return physical units rather than stored counts, applying real = stored * scale + offset from each asset's raster:bands metadata, with no-data masked before the scaling and NaN as the result's no-data. Off by default. Only GDAL assets (GeoTIFF/COG/JPEG2000) are rescaled; netCDF / Zarr / GRIB already unpack the CF packing their own metadata declares.

    It changes how the cube is backed. Single-asset mode normally backs each timestep with the asset URL itself and stays lazy over /vsicurl; a scale cannot be stamped onto a read-only remote handle, so rescale=True instead materialises every timestep that declares a non-identity packing into a local raster under the process artefact root. An asset that declares no raster:bands, or only the identity, keeps its lazy URL. The grouped and multi-asset modes already materialise, so they only change in value.

    Two consequences worth planning for. Units can be inhomogeneous: an item that declares no raster:bands keeps its stored counts while a sibling in the same collection is rescaled, and nothing marks the cube as mixed, so a reduction over the time axis is wrong by the packing factor for that subset. Disk grows per call: the materialised copies that back the returned collection live under the process artefact root until the interpreter exits (see :mod:pyramids.base._artifacts), so a service or notebook rescaling in a loop accumulates one full-resolution raster per timestep per call. Materialising also ends laziness: a rescaled timestep is a local raster, so a later read_part / preview / read_tile can no longer be served from a remote COG's overviews.

Keyed by collection id — resolved per item from item["collection"] / item.collection_id — with a "*" section for cross-collection defaults. Overrides fill gaps only: a value an asset already declares is kept, and the skip warns unless the collection sets warnings: "ignore". Like rescale, applying one materialises the affected timestep; None (default) changes nothing.

    def open_client(
    url: str,
    *,
    signer: Signer | None = None,
    headers: dict[str, str] | None = None,
    timeout: float | None = 30,
) -> Any:
    """Open a STAC API client with a pyramids signer wired into both hooks.

    Args:
        url: STAC API root URL (e.g. an `.../stac/v1` endpoint).
        signer: A :class:`~pyramids.stac.signers.Signer`. Defaults to
            :class:`~pyramids.stac.signers.AnonymousSigner` (no credentials).
            The signer's `sign_item` is passed as the client `modifier` and
            its `sign_request` as the `request_modifier`.
        headers: Optional static HTTP headers added to every request.
        timeout: Per-request timeout in seconds.

    Returns:
        A `pystac_client.Client` instance.

    Raises:
        OptionalPackageDoesNotExist: When `pystac-client` is not installed.

    Examples:
        - Open a public catalog anonymously (requires the `[stac]` extra):
            ```python
            >>> from pyramids.stac import open_client  # doctest: +SKIP
            >>> client = open_client("https://earth-search.aws.element84.com/v1")  # doctest: +SKIP
            >>> search = client.search(collections=["sentinel-2-l2a"], max_items=1)  # doctest: +SKIP
            >>> next(search.items()).collection_id  # doctest: +SKIP
            'sentinel-2-l2a'

            ```
        - Wire a bearer-token signer into both hooks:
            ```python
            >>> from pyramids.stac import open_client, BearerTokenSigner  # doctest: +SKIP
            >>> client = open_client(  # doctest: +SKIP
            ...     "https://stac.dataspace.copernicus.eu/v1",
            ...     signer=BearerTokenSigner(token="my-token"),
            ... )

            ```
    """
    import_pystac_client(_STAC_INSTALL_HINT)
    from pystac_client import Client

    signer = signer or AnonymousSigner()
    # Both hooks are wired unconditionally. For AnonymousSigner sign_item /
    # sign_request are no-ops, so the wiring is harmless; keeping it uniform
    # avoids a branch and means a custom signer never has to be "registered".
    return Client.open(
        url,
        headers=headers,
        timeout=timeout,
        modifier=signer.sign_item,
        request_modifier=signer.sign_request,
    )

    Typed STAC item-search helper (PB-3).

    A thin, typed wrapper over pystac_client.Client.search that makes the common AOI / time / cloud query one call and returns an ItemCollection ready for :meth:pyramids.dataset.DatasetCollection.from_stac. It:

    • opens a client from a URL (or accepts an already-open Client);
    • gates a CQL2 filter on the endpoint advertising the FILTER conformance class, raising a clear error instead of pystac-client's opaque one;
    • accepts a shapely geometry or a GeoJSON dict for intersects;
    • bounds the query at the API — bbox / datetime / max_items / limit are forwarded to client.search so the server (and paging) does the work (M3). This contrasts with :func:pyramids.dataset._stac.from_stac, whose own bbox / max_items are client-side post-filters over an already-materialised item list.

    Two entry points share one query builder:

    • :func:search — eager: returns the matched ItemCollection.
    • :func:item_search — lazy: returns the ItemSearch itself, so the caller can ask for the total hit count (.matched()), stream items (.items()) or walk result pages (.pages()) without materialising everything first.

    That split decides who owns the HTTP session when a URL is passed rather than an open Client. :func:search materialises everything, so the client it opened is closed before it returns (see :mod:pyramids.stac._clients). The lazy ItemSearch keeps issuing requests through its client, so :func:item_search leaves the one it opened open — and releases it only when the query is rejected and nothing is returned. Pass an open Client when that lifetime matters.

    pystac-client is an optional dependency. Install with one of:

    • PyPI: pip install 'pyramids-core[stac]'
    • conda-forge: conda install -c conda-forge pyramids-stac

    def item_search(
    client_or_url: Any,
    collections: str | Sequence[str],
    *,
    ids: str | Sequence[str] | None = None,
    bbox: Sequence[float] | None = None,
    intersects: Any = None,
    datetime: Any = None,
    query: Any = None,
    filter: Any = None,
    sortby: Any = None,
    fields: Any = None,
    max_items: int | None = None,
    limit: int | None = None,
    signer: Any = None,
) -> Any:
    """Build a STAC item search and return the lazy ``ItemSearch`` object.

    Same query as :func:`search`, but nothing is fetched: the returned
    ``pystac_client.ItemSearch`` is the handle to the *unexecuted* search, so the
    caller can ask it for the total hit count or page through results instead of
    materialising every item at once:

    * ``.matched()`` — total number of hits, **or ``None``** when the server does
      not advertise a count (it is an optional STAC API field; never assume it).
    * ``.items()`` — stream items one by one, paging transparently.
    * ``.pages()`` — iterate whole result pages (one request per page).
    * ``.item_collection()`` — materialise everything, exactly what
      :func:`search` returns.

    Args:
        client_or_url: An open ``pystac_client.Client``, or a STAC API root URL
            (opened via :func:`pyramids.stac.open_client`, wiring `signer`).
        collections: Collection id, or a sequence of collection ids, to search.
        ids: Optional item id, or sequence of item ids, to fetch directly.
        bbox: Optional `(minx, miny, maxx, maxy)` lon/lat box, forwarded to the
            API. Mutually exclusive with `intersects` (STAC API rule).
        intersects: Optional AOI geometry — a shapely geometry (anything with a
            ``__geo_interface__``) or a GeoJSON-geometry dict. A shapely geometry
            is converted to GeoJSON before the request.
        datetime: Optional RFC 3339 datetime or interval string
            (e.g. ``"2023-06/2023-08"``), forwarded to the API.
        query: Optional ``query`` extension dict (e.g.
            ``{"eo:cloud_cover": {"lt": 20}}``).
        filter: Optional CQL2 filter (cql2-json dict or cql2-text string). When
            given, the endpoint must advertise the ``FILTER`` conformance class.
        sortby: Optional sort specification forwarded to the API.
        fields: Optional ``fields`` extension selection — an include/exclude dict
            (``{"include": ["id"], "exclude": ["geometry"]}``) or a list of field
            names. Trimming required fields can yield Items that no longer
            validate, so prefer reading such a response as dicts.
        max_items: Optional cap on the total number of items returned (bounds
            paging at the API).
        limit: Optional page size forwarded to the API.
        signer: Optional signer used only when `client_or_url` is a URL (to open
            the client). Ignored when an open client is passed. A client opened
            here stays open, because the returned ``ItemSearch`` reads through
            it; it is closed only if the query is rejected.

    Returns:
        The ``pystac_client.ItemSearch`` for the query, not yet executed.

    Raises:
        OptionalPackageDoesNotExist: When `pystac-client` is not installed.
        ValueError: When both `bbox` and `intersects` are given (mutually
            exclusive per the STAC API spec), or when a `filter` is given but
            the endpoint does not advertise the CQL2 ``FILTER`` conformance
            class.

    Examples:
        - Count the hits before deciding to download anything (requires the
          `[stac]` extra and network access):
            ```python
            >>> from pyramids.stac import item_search  # doctest: +SKIP
            >>> hits = item_search(  # doctest: +SKIP
            ...     "https://earth-search.aws.element84.com/v1",
            ...     "sentinel-2-l2a",
            ...     bbox=(11.0, 46.0, 11.2, 46.2),
            ...     datetime="2023-06/2023-08",
            ... )
            >>> hits.matched()  # None when the server reports no count  # doctest: +SKIP
            128
            >>> first_page = next(hits.pages())  # doctest: +SKIP

            ```
    """
    _reject_both_aois(bbox, intersects)

    import_pystac_client(_STAC_INSTALL_HINT)
    from pystac_client import ConformanceClasses

    opened = isinstance(client_or_url, str)
    client = open_client(client_or_url, signer=signer) if opened else client_or_url
    # The returned `ItemSearch` keeps reading through this client, so it cannot
    # be closed here -- it is released only when the query is rejected and
    # nothing is handed back. `pop_all` is what hands ownership over.
    with contextlib.ExitStack() as stack:
        if opened:
            stack.callback(close_client, client)

        if filter is not None and not client.conforms_to(ConformanceClasses.FILTER):
            raise ValueError(
                "the STAC endpoint does not advertise the CQL2 FILTER conformance "
                "class, so a `filter` cannot be used against it."
            )

        if intersects is not None and hasattr(intersects, "__geo_interface__"):
            intersects = intersects.__geo_interface__

        search_object = client.search(
            collections=collections,
            ids=ids,
            bbox=bbox,
            intersects=intersects,
            datetime=datetime,
            query=query,
            filter=filter,
            sortby=sortby,
            fields=fields,
            max_items=max_items,
            limit=limit,
        )
        stack.pop_all()
    return search_object
